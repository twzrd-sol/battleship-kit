# Incidents

Dated, sanitized, and each one is the reason a piece of the kit exists. Ticket
numbers and internal names are omitted on purpose.

| Date | What happened | What it produced |
|---|---|---|
| 2026-05-17 | An agent edited files in the shared checkout on a feature branch. The main-branch guard did not fire. The shared-tree guard was written the same day the divergence was diagnosed (the PR was opened on 2026-05-17 and merged on 2026-06-05); how long the divergence had been growing is not recorded. | `kit/hooks/pre-commit` shared-tree guard (any branch) |
| 2026-08-20 | Production moved to a single machine. The old rented host stayed up as an unmanaged frozen standby until the provider shut it off: SSH answered, containers ran, scripts exited 0 against it, and four separate stale references to the old environment "succeeded" with confident wrong answers. | LESSONS 1 (merged and green is not verified; read an artifact, not a status) and `kit/ops/backup-health.md` (age, never exit code) |
| 2026-08-25 | A negative claim ("that file is a stale name") was built on `head -5`. The hits were rows 6 and up. | LESSONS 5 (silent truncation) |
| 2026-09-03 | Two agents numbered a migration identically. The loud failure (every PR red) hid the quiet one (the second migration could never apply; a served table was silently absent from production). | LESSONS 1; `kit/ops/deploy-guards.md` (migration numbering, ledger versus image) |
| 2026-09-03 | A scheduled job's installer looked dead (no unit, no references). It was the only refresher of a served table, which had been 15 days stale. | LESSONS 7 (a missing installer is a missing job) |
| 2026-09-03 | A redeploy of an already-deployed image hit a container-name collision after the stop and before the run. Production was dark for about 40 seconds. | `kit/ops/deploy-guards.md` (the collision that leaves a 502) |
| 2026-09-03 | An environment-only redeploy was prepared naming the running tag while another agent shipped two commits. Caught by review; would have started the older build. | `kit/ops/deploy-guards.md` guard 3 |
| 2026-09-05 | A field named for an *evaluation* was assigned from a chain *capability*. Wallets whose lookup failed read as "evaluated, clean", live in production. | LESSONS 3 (`null` is not `false`) |
| 2026-09-18 | 34 PRs were merged in one day with no approving review, the fastest in 3 seconds, every hosted check blocked by a billing hold. Author and merger were one GitHub identity on all 34. The merge check landed at 15:15Z that day. | `kit/ops/honesty-marker.md`, `premerge-check.sh`, `gate-record.sh`, `gate-attest.sh` |
| 2026-09-18 | A merged, deployed fix changed classification for new rows only. The 13 rows it was written for never moved; the commit message read as if they had. | LESSONS 1 (merged and green is not verified) |
| 2026-09-18 | Five headline findings in one audit were artifacts: traffic to a dead route read as demand, one ranked lane read as the whole market (wrong by four orders of magnitude), and three more. Each dissolved on probing the live source. | LESSONS 2 (null results read as findings) |
| 2026-09-18 | Production served a commit that existed on no remote branch. A routine deploy of main would have reverted ten thousand lines of live behaviour. One guard in the deploy script caught it. | LESSONS 6 (live is not on main); `kit/ops/deploy-guards.md` guard 3 |
| 2026-09-18 | A pin check compared two transcriptions of the same fact. Both were stale, both agreed, and main stayed red on the full gate across 19 merges over two days because nobody ran it. | LESSONS 4 (one live side); `gate-attest.sh --run` |
| 2026-09-18 | A session removed four nested worktrees to make a pin test pass. Three were on the operator's keep list; 900+ uncommitted lines were destroyed. They were recovered by replaying tool calls out of agent transcripts. | LESSONS 9; the rule "never remove a worktree to make a test pass" |
| 2026-09-22 | The migration-number collision recurred: two PRs merged about ten seconds apart, each clean against its own base, so a per-PR prefix check could not see it. | `kit/ops/deploy-guards.md` (migration numbering) |
| 2026-09-25 | An hourly anchoring unit failed every hour for a night because its environment file lacked one key. It then began exiting 0 after an unattributed fix; whether the artifact advanced was not checked at the time. | LESSONS 1 again; `kit/ops/backup-health.md` (verify the artifact advanced) |
| 2026-09-28 | A line-by-line audit of a published npm package found a critical bug. Fix built, published, and a security advisory issued the same day; a re-audit then found more, fixed in two further releases within three days. | The local-list mechanism for names under embargo (`PUBLISHING.md` step 1); `kit/rules/02-secret-handling.md` point 2 |
| 2026-09-29 | A power-button press began a poweroff while a VM held the GPU. The shutdown stalled. The hardware watchdog, armed that morning, reset the box in 60 s. The persisted watchdog config turned out not to survive a reboot (kernel blacklist). | `kit/ops/watchdog/` all three files |
| 2026-10-01 | The honesty-marker parser tried to read Markdown the way GitHub renders it, and lost to the renderer repeatedly in one night: a fix that printed a marker inside `<pre>` or `<details>` (caught by a peer session), a reviewer's own note that mentioned a tag and hid both real markers, a stale reject plus a fresh approve counted as two. A ten-reviewer audit the same day then found two more ways to forge an approval and showed that the approach was the problem. The parser now reads only the first line of a comment. | `kit/ops/marker-parse.awk` (first line only), `premerge-check.sh` (fails closed; stale markers dropped before counting), end-to-end tests against a fake `gh`, LESSONS 13, 14 and 16 |
| 2026-10-01 | The kit's own leak gate shipped its denylist inside the tree it guarded: every internal name it protected was committed in all 22 commits and excluded from its own scan. Found while the repo was still private, by asking what a hostile reader of the history would see. A second defect in the same file: the ticket-number pattern began with `#`, was read as a comment, and had never run. | `scan.sh --history`, a generic shipped list plus a local list outside the repo, log-safe output, `export-public.sh`, `PUBLISHING.md`, LESSONS 15 |
| 2026-10-01 | Four rounds of independent adversarial audit of this kit, run before publishing it, each confirmed at least one blocking defect: `pre-push` vouched for a commit it had not tested, `gate-attest --run` for a dirty tree, the leak gate read an invalid pattern as clean, the status board showed green with a production container down, the merge check trusted a date the pusher writes, then a seven-character commit id that a different commit could share, and then a leak scanner that skipped any file named like its own pattern list. The kit's own tests were green while each of these existed. A mutation run over the gating scripts then found checks no test could fail, and the test written for one of them exposed a fail-open in the day's own refactor. | A fix for each, and a test for most; `kit/ops/mutate.py` and CLAIMS say how many; LESSONS 15, 16 and 17 |
| 2026-10-01 | The kit's test suite left a scratch repository behind for every scan case it ran, thousands in a few hours, and exhausted the inodes of the shared temporary directory; another session's gates began failing with out-of-space errors. That session found it, not the kit's tests. | `test.sh` puts every scratch path under one root that is removed on exit; the mutation harness does the same and kills a hung mutant with its whole process group |
